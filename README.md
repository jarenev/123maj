# Majestic: приложение для Android

Одно приложение (APK): ядро на Rust, интерфейс на HTML внутри самого APK. Отдельного сервера и `localhost` нет.

## Что умеет

- **Рынок.** Статистика маркетплейса по серверу: транспорт, предметы, одежда, дома, квартиры, склады, офисы. Введите название предмета и свою цену, и приложение покажет, сколько продано за 7 дней, среднюю, минимальную и максимальную цену, а также где ваша цена относительно рынка.
- **Капты.** Введите название фамы и получите её войны за капты (кто с кем, победитель, карта, дата, игроки с уроном и убийствами) и текущие зоны, которыми она владеет. Кнопка «Все каптов» показывает общую историю.
- **Рейтинг.** Рейтинг организаций по серверу: место, изменение относительно прошлого места, влияние. Можно выбрать период и искать по названию или тегу.

## Чего приложение не может (и почему)

В документации API нет методов, которые дают:
- список предметов конкретного игрока (по нику или статику);
- время, сколько предмет ещё будет стоять на маркете.

Есть только статистика по серверу. Поэтому «сравнение с ценой других» сделано по названию предмета: ваша цена против средней, минимальной и максимальной цены всех выставленных предметов с этим названием. Если у вас есть документация с методом для списка лотов игрока, его можно добавить в `src/ops.rs` (новое действие `player`), но без пути и формата ответа я его не угадываю.

## Требования к сборке

- Rust (rustup), цель `aarch64-linux-android` (скрипт добавит её сам).
- Android NDK (r25 и новее), переменная `ANDROID_NDK_HOME`.
- Android SDK: build-tools и `platforms/android-30`.
- JDK 17.

## Сборка

Linux / macOS / WSL:

```sh
MAJESTIC_API_KEY=ваш_x_api_key ./scripts/build.sh
```

Windows (cmd, в папке проекта):

```bat
set MAJESTIC_API_KEY=ваш_x_api_key
build.bat
```

`build.bat` написан по образцу `build.sh`, но в песочнице не запускался: он проверен только синтаксически. Если сборка упадёт, пришлите вывод ошибки.

Ключ вшивается в библиотеку во время сборки и не хранится в исходниках. Готовый файл появится в `dist/majestic.apk`.

Что важно знать:
- Отладочный ключ подписи `majestic-debug.jks` создаётся при первой сборке. Храните его: новую версию можно поставить поверх старой только при той же подписи.
- Ключ API внутри APK можно извлечь. Этого не избежать, когда ключ лежит в приложении. Не выкладывайте APK публично.
- Лимит API: 5 запросов за 60 секунд. Ядро ждёт освобождения слота, а результаты кэшируются на 5 минут. Кнопка обновления в шапке пропускает кэш.

## Проверка без телефона

```sh
cargo test                       # логика ядра, фикстуры из документации, заголовки HTTP
cargo build --example bridge
python3 tests/e2e/run_e2e.py     # браузерный сценарий через настоящее ядро и мок-API
```

Скриншоты из последнего прогона лежат в `tests/e2e/shots/`.

## Структура

```
src/api.rs        HTTP, заголовок X-API-KEY, лимит, кэш
src/ops.rs        действия интерфейса и нормализация ответов
src/lib.rs        JNI-мост для Android
android/          Java-оболочка: WebView и мост Android.call
assets/index.html интерфейс, стиль из jarenev-style
assets/static/    app.js (логика), app.css, style.css, fx.js, шрифты
scripts/build.sh  сборка APK
tests/            тесты ядра, мок-API и сквозной браузерный тест
```

## Что проверено, а что нет

- Проверено здесь: тесты Rust-ядра (9 шт.), сквозной браузерный сценарий на телефонном и десктопном размере, упаковка APK, подпись v1 и v2, наличие всех файлов в APK.
- Не проверено: сборка самой библиотеки `libmajestic.so` под Android (в песочнице нет NDK и Rust-цели Android), запуск APK на устройстве, работа с боевым API (сеть из песочницы недоступна). Если сборка Rust упадёт, именно на этом шаге, см. сообщение компилятора.

## Сборка с телефона (GitHub Actions)

Файл `.github/workflows/build.yml` собирает APK в облаке GitHub, без компьютера.

1. Создайте аккаунт на github.com и новый приватный репозиторий (кнопка «+» → New repository, галочка Private).
2. Загрузите содержимое папки `majestic` в репозиторий. Через браузер телефона: «Add file» → «Upload files», выберите все файлы. Папки с вложенными подпапками загружаются плохо, поэтому удобнее загрузить с компьютера или через приложение GitHub на ПК.
3. В репозитории: Settings → Secrets and variables → Actions → New repository secret. Имя `MAJESTIC_API_KEY`, значение ваш ключ API.
4. Вкладка Actions → build-apk → Run workflow. Сборка занимает около 10–20 минут.
5. Когда задача завершится зелёной галочкой, откройте её, внизу в Artifacts скачайте `majestic-apk`. Внутри `majestic.apk`.
6. Установите APK на телефон. Android спросит разрешение на установку из неизвестного источника, дайте его.

Важно про подпись: без постоянного ключа каждая сборка подписывается новым ключом, и поставить новую версию поверх старой не получится (придётся удалять приложение). Чтобы этого избежать, при первой сборке скачайте второй артефакт `majestic-keystore-once` (файл `keystore.b64`), откройте его текстом, скопируйте содержимое и добавьте как секрет `MAJESTIC_KEYSTORE_B64`. После этого артефакт можно удалить, а ключ хранить только в секретах. Следующие сборки будут подписаны тем же ключом.
